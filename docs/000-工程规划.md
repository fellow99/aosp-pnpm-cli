## 1. 背景与定位

### 1.1 一句话定位

**以 AAR 形式发布的、Android 版 `pnpm` 命令行可执行**——决策前提（2026-10-30 拍板）：
pnpm 12+ 为 **Rust 独立二进制**，从官方源码（github.com/pnpm/pnpm）交叉编译出
`libpnpm_cli.so`（arm64-v8a，exec 型 PIE）。终端里由 node-pty 经 `forkpty` + `execve`
启动，提供真正的 `pnpm` 命令。Rust `aarch64-linux-android` 为官方 tier2 target，
与 `aosp-uv-cli` 同走 cargo-ndk 交叉编译线。

### 1.2 为什么需要它（独立制品线）

- pnpm 12+ 不再是纯 JS——**不适用“纯 JS 随 node-cli assets 分发”方案**（工作区方案 §3.1
  ⚠ pnpm 例外条目），只能独立成线交叉编译；
- 终端（PTY）需要**独立进程**的 pnpm 命令，而不是进程内调用；
- M2 期间 pnpm 先走 **corepack / JS 基线**兜底（工作区 §9.3），本仓 Rust 线 M3.5 首产后替换。

### 1.3 边界（在范围 / 不在范围）

| 在范围内 | 不在范围内 |
|---|---|
| `libpnpm_cli.so` 的 Rust 交叉编译、exec 门禁、AAR 打包、发布 | JS 版 pnpm 的分发（corepack / aosp-node-cli assets 钉版，M2 基线归处）；npm/npx/corepack 本体（同归 node-cli） |
| 版本事实源 `pnpm-cli.lock.json`（独立 semver，含 openProbes 决策记录） | 任何嵌入 API / 进程内加载形态（实为 NAPI 混合即触发 D4 冻结重评） |
| 运行期 env 注入契约与回程探针定义（§7） | 环境引导层的实现（bridge 载荷 / Kotlin，消费方职责）；node 本体（`io.github.fellow99:node-cli`） |
| pnpm 生态行为边界声明（`self-update` 禁用、平台二进制包限制，§7） | pnpm store / 缓存目录的长期治理（运行期生成于消费方 filesDir，自管） |

## 2. 版本规则

  对 node-cli 只有**运行期依赖**，不是版本配对（兼容下限 ⬜ M3.5 首产时声明）；

## 3. 总体架构与关键决策

```
┌─ 消费方 App 进程 ─────────────────────────────────────────────────────┐
│  环境引导层（bridge 载荷或 Kotlin）                                    │
│   - 注入 PATH / HOME / TMPDIR / XDG_DATA_HOME⬜ / LD_LIBRARY_PATH /    │
│     npm_config_*（§7 注入表）                                          │
│   - node 由 aosp-node-cli 供给：libnode_cli.so 与 libpnpm_cli.so 同在   │
│     nativeLibraryDir；命令名 `node` 经 symlink 农场 $HOME/bin 提供      │
│        │ pty.spawn(<nativeLibraryDir>/libpnpm_cli.so, …)               │
│        ▼                                                               │
│  pnpm 子进程（exec 型，独立生命周期；forkpty → setsid → TIOCSCTTY）      │
│   - package lifecycle scripts（JS）⇒ 经 PATH 上的 node 再启动子进程     │
│   - store / 缓存 / 配置 ⇒ filesDir（§7 注入表；nativeLibraryDir 只读）   │
└───────────────────────────────────────────────────────────────────────┘
```

### 3.1 关键决策记录（不可回归项）

### 4.2 工具链与源钉选

| 项 | 取值 | 说明 |
|---|---|---|
| pnpm 源 | `github.com/pnpm/pnpm` tag `v<pnpmver>` tarball，SHA-256 校验 | fetch 不改源；版本钉选见 §2 |
| Cargo.lock | 随源码树钉定；**依赖 sha 记录粒度 ⬜**（M3.5-T3 定案）：候选取向 a) 整文件 sha256 记入 lock.builtFrom；b) per-crate cargo checksum（随 Release 归档 Cargo.lock 副本）；c) cargo license 报告归档（许可必选） | 可复现性关键；倾向 a+b+c 组合 |
| Rust target | `aarch64-linux-android`（官方 tier2，`rustup target add`） | stable 工具链 ⬜ 版本首产钉 |
| cargo-ndk | 交叉编译胶水（NDK linker 选择、`-C link-arg` 注入） | 版本钉选 ⬜ 首轮定 |
| NDK | 与 aosp-node-runtime 对齐线 ⬜ | lock.builtFrom.ndk 首产回写（现 TBD） |
| link 参数 | `-C link-arg=-Wl,-z,max-page-size=16384` | 16KB 页设备硬要求（C4） |
| libc++ | DT_NEEDED 是否实际出现 `libc++_shared.so` 以首产为准 ⬜；在白名单内（lock 登记），不随包（D6，消费方 node-runtime 供给） | |
| strip | `llvm-strip --strip-unneeded`（NDK 自带）→ `libpnpm_cli.so` | 命名 = `lib<工具>_cli.so` 约定（§9.1 工作区方案） |
| androidApi | 24（minSdk；lock `androidApi=24`） | linker target `aarch64-linux-android24` |

### 4.3 交叉编译流程（build-pnpm-cli-android.sh，M3.5 实现）

```
① env：rustup target add aarch64-linux-android；cargo-ndk；NDK=<ndk>（API 24 linker）
② fetch：pnpm v<ver> tarball → SHA-256 校验 → .dist/src/pnpm-src/（源不改）
③ 依赖盘点：Cargo.lock → cargo license 清单（许可归档用）+ 依赖 sha 记录（粒度 §4.2）
④ cargo build --release --target aarch64-linux-android
   RUSTFLAGS="-C link-arg=-Wl,-z,max-page-size=16384"（或经 cargo-ndk 注入）
⑤ strip：llvm-strip --strip-unneeded → libpnpm_cli.so
⑥ ELF 门禁：provision --inspect（ET_DYN + PT_INTERP + NEEDED 白名单 + 16KB + sha/size 记录）
⑦ BUILD-METADATA.txt / FETCH-METADATA.json（镜像 pty 归档形态）
```

要点与风险：

- **依赖可编性是 M3.5 最大不确定项**（探针②前置，§4.1）；不可编项的处置直接决定 M3.5 走向；
- **DT_NEEDED 实际清单**（`libc++_shared.so` 是否出现）首产核实，白名单口径 §6；
- **体积 ⬜**：首产实测回填 lock（参考同线 uv ≈25–40MB 量级，仅作量级参照）。

## 5. 制品形态与打包投放（AAR）

```
pnpm-cli-<ver>.aar
├── jni/arm64-v8a/libpnpm_cli.so      # exec 型 PIE（ET_DYN + PT_INTERP=/system/bin/linker64，16KB 对齐）
└── META-INF/pnpm-cli.properties      # tool.version / abi / name / size / sha256 / provisionedAt
                                      # （provision 投放时已生成；无 assets——D8）
```

- 打包：**`useLegacyPackaging=true`**（D1，已设）；模块只作 AAR 容器，无任何 Kotlin/Java 源；
- **无壳脚本**：pnpm 本体即命令入口（D8）；npm/corepack 的 JS 壳脚本入口不适用于本仓；
- provision（**M0 已完整实现**）：`--out/--from` 投放、`--check` 校验（含 jniLibs 兄弟文件
  唯一性：仅 `libpnpm_cli.so`，禁入 `libnode.so`）、`--inspect` 只读门禁；退出码 0/2/1；
  draft 只记录不比对；`--allow-page-align-4k` 仅 bring-up 放行（上架/16KB 设备不合格）；
- **M3.5 预期无 provision 扩展**（单二进制、无 assets）——若首产 DT_NEEDED 出现白名单外库，
  回 §4.3 ④处置（feature 裁剪 / 静态化），不改门禁口径。

## 6. exec 型门禁 profile

| 门禁 | 判据 | 与 pty（dlopen 库）门禁的差异 |
|---|---|---|
| ELF 形态 | `ET_DYN`（PIE） | 同 |
| 解释器 | **PT_INTERP 恰 1 个且 = `/system/bin/linker64`** | **相反**（pty 要求 PT_INTERP=0） |
| 依赖 | **DT_NEEDED 白名单**：系统库（libc/libm/libdl/libz/liblog）+ **`libc++_shared.so`**（lock 登记，不随包——D6，node-runtime 供给） | pty 是“必须含 libnode.so” |
| NAPI | 无门禁（独立进程，不解析 napi_*） | pty 有“napi_* 未定义引用”门禁 |
| 页对齐 | 16KB（`-Wl,-z,max-page-size=16384`） | 同 |
| 命名 | `libpnpm_cli.so`（`lib<工具>_cli.so` 约定；**禁 `libnode.so`**） | exec 型新增 |
| 出处 | sha256 / size / 源版本 / NDK / flags | 同 |

- **已实现（M0）**：provision 退出码 0/2/1，draft 只记录不比对（①–⑦ 门禁项
  `tools/provision.mjs`）；
- **M3.5**：白名单实际口径核对（首产 DT_NEEDED 实测）⬜；无新增门禁计划。

## 7. 运行期契约（消费方 / 环境引导层）

**依赖前提**：package lifecycle scripts 是 JS，由 PATH 上的 node 执行 ⇒ 消费方必须配
`io.github.fellow99:node-cli`（README 用法示例已给：`runtimeOnly("io.github.fellow99:node-cli:$nodeVer")`）。

| 环境变量 | 值 | 说明 |
|---|---|---|
| `PATH` | `<nativeLibraryDir>:$HOME/bin:/system/bin` | nativeLibraryDir 提供 pnpm 本体；**命令名 `node`** 经 symlink 农场 `$HOME/bin/node → $NLDIR/libnode_cli.so`（node-cli 线引导，工作区 §4.3）或消费方等价注入——缺失则 lifecycle scripts 失败 |
| `HOME` | `<filesDir>/home` | pnpm 配置 / 缓存基座（`.config/pnpm`、`.cache/pnpm`） |
| `TMPDIR` | `<filesDir>/tmp` | 临时目录 |
| store 目录 | **⬜ 择一（M3.5-T7 探针 P3 定案）**：a) 注入 `XDG_DATA_HOME=<filesDir>/.local/share`（依赖 pnpm 默认落点 `$XDG_DATA_HOME/pnpm/store` 的实际解析 ⬜）；b) 显式 `pnpm config set store-dir <filesDir>/pnpm/store`（显式可核验、`pnpm store path` 直接回读；配置文件落 HOME 下） | 目的相同：store（可达 GB 级）必须落 filesDir，**绝不落 nativeLibraryDir（只读）**；a 无需首启命令、b 语义显式 |
| `npm_config_*` | 透传（`npm_config_registry`、`npm_config_proxy` 等） | pnpm 兼容 npm 配置环境变量；消费方按需注入 |
| `LD_LIBRARY_PATH` | `<nativeLibraryDir>` | exec 子进程走默认 linker namespace，看不到 App 库目录（工作区 §2 次级约束）；`libc++_shared.so`（若 DT_NEEDED）由 node-runtime 供给、同在 nativeLibraryDir |
| TLS 根证书 | ⬜ pnpm（Rust 栈）证书来源：rustls webpki-roots 自带 vs 需 CA 文件注入——M3.5 探针核实；若需文件则经 `npm_config_cafile` 或专用 env | Android 无 `/etc/ssl/certs`；影响 P2/P7 网络回程 |

- **已知限制（消费方文档必须写明）**：
  1. **必须配 node-cli**：未注入 `node` 时，带 lifecycle scripts 的包 `pnpm install` 失败；
  2. **`pnpm self-update` 不可用**（D7）：nativeLibraryDir 只读，物理不可能成功 + C2 红线；
     升级唯一走制品线新版本；
  3. **生态包自带平台二进制（esbuild/biome 式 optionalDependencies）在 pnpm 安装时会在运行期
     下载平台 .so——触碰 C2 红线**。能力边界：纯 JS 包安全；含平台二进制的包不可用，
     文档声明口径 ⬜ M3.5 评估（registry 过滤 / 能力标志，绝不静默降级）；
  4. `pnpm install -g` 的全局 bin 落 filesDir（HOME 注入基座）⇒ 全局安装包**自带的二进制**
     不可直接 exec（C1，同工作区 §3.1 npm 已知限制）；其 JS 入口经 `pnpm exec` 走 node 可用 ⬜。

## 8. 唯一事实源：`pnpm-cli.lock.json`

镜像 pty/node-cli 纪律：版本 + 大小 + sha256 + 门禁 + 出处，二进制不入库。当前唯一 release
为 **draft**（12.0.0 计划版本；size=0、sha256 空）——draft 不伪造哈希，首个真实 CI 构建
