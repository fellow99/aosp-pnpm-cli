## 1. 背景与定位

**以 AAR 形式发布的、Android 版 `pnpm` 命令行可执行**——pnpm 12+ 为 Rust 独立二进制，
从官方源码交叉编译出 `libpnpm_cli.so`（arm64-v8a，exec 型 PIE）。

**运行期依赖**：package lifecycle scripts 是 JS，由 PATH 上的 node 执行——
消费方必须配 `io.github.fellow99:node-cli`。本 AAR 不是孤岛。

边界：只管 pnpm 本体；npm/corepack 随 aosp-node-cli assets 分发；M2 阶段 pnpm 先走
corepack/JS 基线，本仓 Rust 版在 M3.5 接管。

## 2. 版本规则

制品版本 = pnpm 上游版本，独立 semver；升级 = lock 增项 + CI 重建。

## 3. 技术方案

- 制品：`jni/arm64-v8a/libpnpm_cli.so`（exec 型 PIE，16KB 对齐）；无 assets；
- 构建：rust aarch64-linux-android + cargo-ndk；`-C link-arg=-Wl,-z,max-page-size=16384`；
- 门禁：exec profile 同款；`libc++_shared.so` 在白名单内但不随包（node-runtime 供给）；
- 纪律：不下载上游预编译二进制（上游 android-arm64 分发大概率不存在，见 openProbes）。

**遗留探针（lock.openProbes，不阻塞建仓，阻塞 M3.5 出口）**：
① 上游 android-arm64 平台二进制可得性；② Rust 依赖（napi-rs？ring？）可编性试编；
③ 若前提被推翻（NAPI 混合形态）→ 冻结本仓、按 pty 式伴生件重评。

## 4. 里程碑

- **M0 骨架（本文件）**：✅
- **M2（基线期）**：pnpm 命令经 corepack/JS 基线可用（不依赖本仓）。⬜
- **M3.5 Rust 线**：探针 ①② → cargo 交叉编译过门禁 → Release → 替换 JS 基线。⬜
- **M4 Maven Central + 跟随机制**。⬜

### 4.1 发布模式（GitHub Release 先行、Maven Central 随后）

沿用 aosp-node-pty 的两段式发布：

1. **先行：GitHub Release（M3.5，tag `v<pnpmver>` 推送触发；前置 openProbes ①② 通过）**——
   归档 `pnpm-cli-v<ver>-android-arm64-v8a.tar.gz`（libpnpm_cli.so + 元数据 + LICENSES +
   cargo 依赖许可清单）与 `.sha256`，lock 回写；
2. **随后：Maven Central（M4）**——执行口径按工作区
   [`docs/发布到maven-central.md`](../../docs/发布到maven-central.md) runbook（§2 一次性凭据 →
   §4 发布前检查 → §5 上传 → §6 核验回填）；RELEASE=false 默认。

- 与 pty 的差异：版本源 `CLI_VERSION`（= pnpm 上游版本，独立 semver）；**运行期依赖
  node-cli**（POM description 已声明）；M2 期间 pnpm 先走 corepack/JS 基线，本仓 Rust 线
  首产后替换（runbook §10 已登记本线复用）。

## 5. 质量门禁汇总

exec profile 门禁（同 node-cli）+ 不入库 + 可复现 + 许可（pnpm MIT + cargo 依赖清单随
Release 分发）+ 发布卫生（RELEASE=false 默认）。
